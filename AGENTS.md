# AGENTS.md

Guidance for AI coding agents and contributors working on **dotgo**.
[فارسی](AGENTS.fa.md)

## What this is
A Go TUI (bubbletea + lipgloss) that manages dotfiles across machines in a git repo, usually a bare repo at `~/.dotfiles`.
It shells out to the `git` CLI; there is no libgit2 and no git re-implementation. User docs: [README](README.md), [usage guide](docs/USAGE.md).

## Commands
```sh
go vet ./... && go test ./...      # must pass before every commit (CI runs it on Linux and macOS)
go run ./cmd/dotgo                 # run the TUI
go build -o dotgo ./cmd/dotgo      # build (version is injected at release via -ldflags "-X main.version=…")
```
Tests must not touch the real `$HOME` or repo: use `t.TempDir()`, and set `GIT_CONFIG_GLOBAL=/dev/null` and `GIT_AUTHOR_*`/`GIT_COMMITTER_*` when creating commits (see `internal/gitx/gitx_test.go`).

## Layout
| Path | Responsibility |
|---|---|
| `cmd/dotgo` | CLI entry: `init`, `config`, `version`, default = TUI. Flag parsing only. |
| `internal/config` | Per-machine JSON config (load/save/expand). |
| `internal/gitx` | Thin `git` wrapper (`Client`): status, ls-files, variants, push/pull. No UI. |
| `internal/diff` | Pure text helpers: LCS line diff, hunks (`Patch()` for `git apply`), unified diff. |
| `internal/variant` | `Pick` (host beats os) and `Apply` (copy/symlink + `.dotgo-bak`). |
| `internal/secrets` | `Looks(path)` — credential-looking names. |
| `internal/initflow` | First-machine / join-machine setup. |
| `internal/tui` | `model.go` state + actions, `update.go` keys/mouse, `view.go` layout, `render.go` diff rendering, `styles.go`. |

Dependencies point inward: `tui` → `gitx`/`diff`/`variant`/`secrets`; `cmd` → everything; the leaf packages import nothing from each other except `initflow` → `config`, `gitx`, `variant`.

## Conventions
- Keep it small and boring: standard library first, no new dependency without a reason, no interface with one implementation.
- Logic goes in `internal/*` (testable, no terminal); `tui` only wires keys → actions → views. Add a test with every non-trivial logic change.
- All git access goes through `gitx.Client`; never build ad-hoc `exec.Command("git", …)` elsewhere (except `initflow`, which runs before a repo exists).
- **Safety rules (do not weaken):** destructive actions (discard, apply variant, staging a secret-looking file) must show a preview and require `y`; never delete user files — back them up (`.dotgo-bak`, `.dotgo-backup/`); the Remote tab is read-only and key-based ssh only (`BatchMode=yes`).
- Never commit secrets, private keys or real `$HOME` paths.
- The TUI must not wrap or overflow: clip long lines (`clip`/`ansiTrunc`), and keep `View()` side-effect free.
- Variant naming is a public contract: `<base>##host.<name>` beats `<base>##os.<goos>` (case-insensitive).

## Git workflow
- Work on `develop`. Open a PR to `main` and **squash-merge**. No direct pushes to `main`.
- The **PR title / squash message must be a [Conventional Commit](https://www.conventionalcommits.org/)** — [semantic-release](https://github.com/semantic-release/semantic-release) reads it on `main` to pick the version and write the release notes:

  | Type | Release |
  |---|---|
  | `fix:` | patch |
  | `feat:` | minor |
  | `feat!:` or a `BREAKING CHANGE:` footer | major |
  | `docs:`, `chore:`, `refactor:`, `test:`, `ci:` | no release |

- Do not add co-author / "generated by" trailers to commits or PR descriptions.
- Releases are fully automatic (`.github/workflows/release.yml`): tag, GitHub release notes, and `linux`/`darwin` × `amd64`/`arm64` archives. Never tag or edit releases by hand.
